Installing a pack or adding an `extends` source no longer replaces the MCP servers, permissions, hooks or ignore patterns you already have in your tools. Before, when your own canonical file did not manage a setting (no `mcp.json` or no `mcpServers` key, a `permissions.yaml` or `hooks.yaml` that was missing or had only comments, or an `ignore` file with no patterns), the pack's values became the whole list, and `generate` replaced that setting in each tool's config, for example the servers in `~/.claude.json`, the permissions and hooks in `.claude/settings.json`, or a hand-written `.cursorignore`. This happened in project and global scope, also with `--accept-mcp`, `--accept-permissions` and `--accept-hooks` for remote packs.

Now values from packs and `extends` join only settings you manage. For anything else, `generate` prints one warning per setting and leaves your tools' own values alone; the pack stays installed. Permissions count list by list: a pack's `deny` list is used only if your own `permissions.yaml` has a `deny` list. Once `hooks.yaml` manages hooks, pack hooks are still never dropped by another layer. To use a pack's values, run `agentsmesh import --from <tool>` (add `--global` for `~/.agentsmesh`) to copy in what your tools already have, or write the setting yourself, then run `agentsmesh generate`.

**Upgrade note:** a project that took all of its MCP servers, permissions, hooks or ignore patterns from packs or `extends` now gets a warning, and the next `generate` stops writing them: depending on the tool, it removes the file it wrote from those values or leaves the old entries in place. This matters most for ignore patterns: an ignore file AgentsMesh wrote from a pack or `extends` source (for example one that hid `.env`) is removed, so add those patterns to your own `.agentsmesh/ignore` before you run `generate`. To keep using the other settings, opt in once: list your servers under `"mcpServers"` in `.agentsmesh/mcp.json` (`agentsmesh import --from <tool>` copies in the ones your tools have; `{}` is fine for a project with no servers of its own, but never leave it empty in `~/.agentsmesh/mcp.json`, where an empty list makes Claude Code, Zed and Goose drop every global server), add the empty lists you want (`allow: []`, `deny: []`, `ask: []`) to `permissions.yaml`, `{}` to `hooks.yaml` (the same files under `~/.agentsmesh` with `--global`). To stop the warning instead, leave that feature out of the pack's or the `extends` entry's `features`.
